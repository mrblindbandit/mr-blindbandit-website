01

Covered tools

The Media Suite may include an audio and video-to-audio converter, clipper, silence trimmer, audio normalizer, loudness and quality checker, metadata editor, waveform image generator, artwork resizer and platform artwork pack, audiogram generator, art-track generator, lyric-video generator, thumbnail tools, presets, and related browser utilities.

02

Local-first design

Where practical, Media Suite tools should process selected files locally in the browser. Local-first processing reduces unnecessary upload of source media and can improve privacy. A tool that sends a source file to a server, cloud renderer, AI provider, storage bucket, or another third party must disclose that fact before the transfer occurs.

03

Rights to source material

Users may process only files and content they own, have permission to use, or are otherwise legally entitled to process. The fact that a file can be selected from a device does not prove ownership or permission.

04

No DRM or stream circumvention

The Media Suite is not a service for ripping protected streams, defeating digital rights management, bypassing paywalls or access controls, or extracting copyrighted media from services where the user lacks authorization. Features should not be marketed as tools for circumventing access restrictions.

05

Art-track generator

The art-track generator can combine user-supplied audio, artwork, metadata, text, and visual layout into a rendered video or project. The user is responsible for rights to the recording, composition, artwork, logos, photographs, fonts, and metadata. Generating an art-track file does not create YouTube Music, Content ID, distributor, DDEX, Apple, Spotify, or other platform approval.

06

Audiogram generator

The audiogram generator can combine audio with waveform or progress visuals, artwork, captions, text, and branding. Any captions or transcripts generated or entered by the user should be reviewed for accuracy before publication. The tool does not guarantee platform-specific safe zones, advertising approval, caption certification, or legal accessibility by itself.

07

Clipper and silence trimmer

Clipping and trimming can permanently change duration, fades, transients, metadata, timing, or synchronization in exported copies. The interface should show selected start/end values in text, allow precise keyboard-accessible entry, and warn before replacing a file if replacement is ever supported. Original source files should remain untouched by default.

08

Loudness and normalization

Loudness analysis and normalization are technical tools, not mastering guarantees. Integrated LUFS, true peak, sample peak, dynamic range, and platform presets can help users prepare media, but different platforms can transcode, normalize, reject, or alter playback independently. Presets should be described as targets or workflows, not guarantees that a distributor or DSP will accept a file.

09

High-resolution and professional presets

A high sample rate or bit depth does not restore information absent from the source. Upsampling a low-quality source does not create a genuine high-resolution master. The site should avoid representing ordinary transcoding as Apple Digital Masters certification, distributor certification, or mastering by an approved mastering house unless that status is actually held.

10

Metadata editor

Metadata tools can modify tags such as title, artist, album, track number, artwork, comments, or standard identifiers supported by the output format. Users must verify metadata before distribution. Editing an ISRC, UPC, copyright notice, composer field, or ownership field does not create a legal right or identifier assignment that the user does not have.

11

Artwork tools

Artwork resizing and platform presets are convenience tools. Platform requirements can change. Users should verify current distributor or platform specifications before final delivery. Upscaling does not guarantee improved visual quality, and automated crops can remove important content.

12

Lyric video tools

Users are responsible for rights to lyrics, compositions, recordings, images, and video elements. Timecoded lyrics should be reviewed manually. A lyric video can require both sound-recording and composition permissions depending on use and territory.

13

Accessibility requirements for generated media tools

Every Media Suite control must be operable without dragging as the sole method. Timeline, crop, and trim values should have labeled numeric or text controls; keyboard actions should be documented; preview-only visual information must have a text equivalent; progress and completion states should be announced to assistive technology; and validation errors should be programmatically associated with the affected controls.

Waveforms, meters, colors, and graphs must not be the only way to communicate loudness, clipping, timing, selected ranges, or errors. The interface should expose values as readable text. Canvas-based editors require an accessible control model outside the canvas.

14

Browser resources and performance

Large media operations can consume substantial memory, CPU, battery, and storage. A browser may crash, suspend a tab, terminate a WebAssembly process, or fail to complete a render. The service does not guarantee successful processing of every file or device. File-size and duration guidance should be shown before expensive processing where practical.

15

Quality and compatibility

Output quality depends on the source, codec, settings, browser, library versions, and export format. Lossy transcoding can reduce quality. Some metadata or codecs are not supported in every container or browser. Users should retain original files and test exports before replacing production masters.

16

Temporary files

Browser-generated temporary files, object URLs, and caches should be released when reasonably possible after processing or navigation. If server-side temporary files are introduced, they should use a documented automatic-deletion period and access controls, with the privacy notice updated before launch.

17

Third-party software and open-source licenses

The Media Suite may use open-source or third-party software such as FFmpeg-derived WebAssembly, codecs, parsers, rendering libraries, or content-delivery services. The operator must preserve copyright notices, provide license information, and meet source-offer, relinking, attribution, or distribution requirements applicable to the exact build and license configuration used.

The site must not assume that every FFmpeg build is subject to the same license. The actual compilation flags and included libraries determine obligations and must be audited before production distribution.

18

No platform affiliation

Unless expressly stated, presets or names referring to a streaming platform, distributor, social network, or file standard describe compatibility targets only. They do not imply sponsorship, certification, endorsement, partnership, preferred-vendor status, or guaranteed acceptance by the named organization.

19

User responsibility and backups

Users should retain originals and independent backups. The operator is not responsible for a user's decision to delete source media after creating an export. Any replacement or destructive workflow should use an explicit confirmation step.

20

Abuse controls

The service may impose reasonable file-size, duration, concurrency, rate, browser-resource, or feature limits to maintain availability and prevent abuse. Circumventing limits through automated requests or account manipulation is prohibited.

Professional review notice

These public documents explain current website practices and user expectations. They are not a substitute for advice from a lawyer or regulator about a particular person, contract, jurisdiction, or dispute. Applicable rights that cannot lawfully be waived remain available.
