# Blindbandit Records label portal

The public site is generated by `python scripts/portal.py` (imports earlier generators). The portal has independent Better Auth password accounts, D1 records, and private R2 PDF files. It does not share client sessions or permissions with the fan community. Production public signup is disabled at the Worker route allowlist; administrators provision invitation-only accounts.

## Runtime configuration

- RESEND_API_KEY: private, sending-scoped API key in Sites environment secrets.
- PORTAL_AUTH_SECRET: private, at least 32 cryptographically random characters. Rotating invalidates signed session cookies.
- PORTAL_EMAIL_FROM: verified Resend sender, currently `Blindbandit Records <accounts@mrblindbandit.net>` by default.
- PORTAL_SETUP_TOKEN: one-time, single-purpose deployment secret for POST /api/portal/bootstrap with Bearer authorization. Creates only the fixed requested owner at business@mrblindbandit.net and attempts an invitation. It never returns a password or reset token. Successful provisioning is recorded as label_settings.owner_bootstrap so subsequent calls cannot create more owners or resend mail. Remove the environment secret after provisioning.
- COMMUNITY_MODERATOR_EMAIL: existing verified site-owner ChatGPT identity, also permits the owner to enter the portal if email delivery is unavailable. It does not grant other community members label access.

Never commit credentials, bootstrap tokens, session tokens, or password links. Auth forms use same-origin HTTPS. Reset tokens are carried in the URL fragment and removed from browser history after being read. Better Auth hashes passwords, signs secure HttpOnly cookies, consumes reset tokens once, and revokes sessions after password resets. D1 counters enforce limits across Worker instances. Every data API separately enforces membership, role, and client ownership. Role or account status changes revoke existing label sessions.

## Roles

Owner: all label records and staff roles, protected from client/account API demotion.
Administrator: clients, manager/accountant invitations, label records, inbox, audit. Cannot change owners or other administrators.
Manager: client directory, earnings read, contracts, messages, and tasks.
Accountant: client directory, earnings create/read, messages, and task read.
Client: own earnings, own contract downloads/review acknowledgments, own messages/tasks/profile.

Client identities retain the client role so their records stay isolated. Create a separate staff account when a client also works for the label. Public API tokens, payout integrations, distributor imports, electronic signatures, marketing automation, and self-service erasure are not implemented. Financial amounts are integer minor units; supported currencies all use two decimal places. Ledger entries are manual and must not be presented as a live bank balance. Current lists are bounded; CSV exports reflect returned rows.

## Email delivery

The password and invitation templates contain HTML branding, a plain-text alternative, copyright, support and privacy links. label_mail records `pending`, `accepted`, or `failed`. Resend acceptance is not an inbox delivery receipt. A failed invitation leaves the account saved; an administrator can resend after sender verification. An email provider failure never silently generates a successful invitation status.

Resend domain verification requires Resend domain-management access and adding its exact DNS records to Cloudflare. A sending-only key cannot retrieve or edit domains. Do not guess DKIM records, replace existing mailbox MX records, or claim DNS changes without a successful DNS write.

## Verification

`node --test tests/portal.test.mjs tests/community.test.mjs` uses a SQLite-backed D1 adapter and simulated email/R2 services. It checks native password setup/sign-in, one-time reset consumption, secure cookies, private record isolation, role protection, CSRF, account suspension, and failed delivery reporting. It does not send email. Run the Sites build helper for the production Worker; generate and inspect append-only Drizzle migrations before publishing.
