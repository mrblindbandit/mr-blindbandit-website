# Mr. Blind Bandit

## Current implementation (September 2026)

The current site is a 65-page Vinext/Cloudflare Worker application. Author pages in
`scripts/` and browser assets in `public/`. Run `python scripts/portal.py` to rebuild
all authored HTML, including the final SEO pass. The historical notes below describe
earlier editions and are not the current deployment procedure.

The Sites manifest identifies the existing project. Use the Sites build and hosting
helpers to publish its Worker, public assets, D1 migrations and R2 binding. Never edit
previously applied migrations. The custom domain is `https://mrblindbandit.net`.

The label portal has invitation-only Better Auth email/password accounts. The public
fan community keeps its separate ChatGPT identity. Owner and label records are checked
on the server; the public navigation must not expose the owner inbox. Password reset
requests for an unverified invited account send an invitation. Resend acceptance and
failure are saved to the private activity log; redacted Worker events contain no
recipient addresses, passwords or reset links.

Private HTML is compiled into `worker/private-pages.ts` and returned only after the
Worker authorizes the request. The build removes those documents from `dist/client`
using `scripts/protect-private-pages.mjs`, because Cloudflare's static-asset delivery
can otherwise bypass Worker page guards. Keep this build step and verify private
documents are absent from the deployment archive. Public login/reset pages remain
static; financial and account APIs always enforce their own authorization.

Optional label social sign-in uses `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`,
`APPLE_CLIENT_ID` and `APPLE_CLIENT_SECRET` in protected runtime environment settings.
Store both client secrets as secrets. Apple uses a signed client-secret JWT, which
must be renewed before expiry. Register these exact HTTPS callback URLs:

- `https://mrblindbandit.net/api/label-auth/callback/google`
- `https://mrblindbandit.net/api/label-auth/callback/apple`

Register the website domain with each provider and publish the provider's consent
configuration as applicable. Buttons remain absent until credentials are configured.
Users first activate their invitation and sign in with a label password, then connect
their provider under Account & security. Implicit email-based linking and social
signup are disabled; only existing, active memberships may create sessions. Provider
linking never changes a role. Apple form-post callbacks use Better Auth's state and
token verification; application writes retain same-origin checks. Real OAuth callback
verification requires the owner's Google/Apple developer configuration.

SEO is generated by `scripts/seo.py`: unique public titles/descriptions, canonical
URLs, Open Graph/Twitter metadata, accurate JSON-LD, matching breadcrumbs, related
links and an XML sitemap containing public pages only. Account/private pages remain
noindex. Robots allows public crawling and names the sitemap. The press attribution
kit helps media link to the site; it does not create links on external websites.
Search Console ownership and Google's actual indexing remain external account steps.

A static artist website for Mr. Blindbandit with selected releases, opt-in Spotify and YouTube players, biography, verified artist links, and business contact.

## Content

All public assets are authored in `dist/`. No compilation or framework dependency is required. Update `dist/index.html` for copy and artist links, `dist/styles.css` for styling, and `dist/app.js` for interactions.

The site provides keyboard navigation, a skip link, responsive layout, visible focus states, reduced-motion support, and a direct music/contact fallback. Media providers are contacted only when their player is activated. Business contact uses the visitor's email app; no form data is collected.

## Cloudflare deployment

Upload the contents of `dist/` to a Cloudflare Pages Direct Upload project. Alternatively, with Cloudflare Wrangler authenticated in the intended account, deploy with `npx wrangler pages deploy dist --project-name mr-blind-bandit` after creating the named Pages project. Deployment remains pending until the user's own Cloudflare account is connected and the target project can be verified.

The `.openai/hosting.json` file identifies the independently saved Sites project and review version. It is not evidence of deployment to the user's Cloudflare account.

## Expanded edition
Eight static pages: home, music, collaborators, story, videos, connect, press, support. Edit scripts/build.py and data/catalog.json, then run `python scripts/build.py`. Shared styles and interactions are authored in dist/styles.css and dist/app.js. No framework dependencies. Motion is enabled by default with a manual pause control. Third-party media only loads on request; audio is never started on page load. Payment information is provided by the owner; no payments are processed on this site.

## Full label edition
Build the complete 28-page website with `python scripts/expand.py`. Form IDs and verified public URLs are in data/forms.json. Jotform stores submissions and mailing-list signups in the owner account; no email campaign is configured. Domain mrblindbandit.net is active. submit, label, and music subdomains require DNS validation before activation.

## Connected community edition
The site now has 51 pages. Author static content with `python scripts/accounts.py`; shared browser code and styles are in public/. The Vinext Worker serves those assets and implements community and native form APIs. Build with the Sites build helper. D1 persists profiles, posts, comments, votes, reports, and private form entries. R2 stores optional private audio uploads. Sign-in is dispatch-owned ChatGPT authentication; the owner email is configured as a secret runtime variable, never in browser code. The owner inbox is /owner/inbox/ and moderation is /community/moderation/. Browser preferences are local only. Jotform embeds were replaced with native forms after external authentication failed. No email campaign is configured.

Verification: Node API tests exercise anonymous/write boundaries, cross-user restrictions, posts/comments, reports, votes, rate limits, native forms, private file download/deletion, profiles and dashboards with SQLite. All public links, labels, headings, and page entries are checked before publishing. Browser UI QA was not requested.
